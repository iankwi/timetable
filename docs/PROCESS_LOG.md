## 第 5 轮：Bug 复现与修复

- **Bug：周视图列头显示周二~周六**。用户报告后用 browser-use（390×844 视口）复现成功
- 根因：JS 数组 0 起始，`WD[w]`（w 从 1 开始）取标签偏一天；`WD[d.getDay()]` 在周日的映射也是错的
- 修复：业务索引 WD（1=周一）与 JS 索引 WDS（0=周日）分离，标签统一 `WD[w-1]` / `WDS[getDay()]`
- 回归验证：列头周一~五 ✓；月视图 8 月全月学期外 ✓；9/1(周二) 仅第5节六.4 ✓；10/1(周四) 三节课 ✓
- 教训：**涉及"第 X 个"的语义（星期、节次），必须先写清楚索引基准再动手；改动后要在真实视口尺寸下渲染验证，不能只看代码**

## 2026-08-29 第 6 轮：周视图格子空白 + 拖拽/滑动失效（browser-use 全链路验证）

用户反馈：周视图看不到格子内容；浏览器拖动无效；左右滑动不行。

| 问题 | 根因 | 修复 |
|------|------|------|
| 格子有底色但无内容 | 格子内容走 lessonsOn()（含学期过滤），假期中全部为空 | 网格改为显示固定课表模板（baseAt），学期过滤只作用于"实际课程"视图（今天/面板/月历） |
| 拖动无效 | 连带问题：格子无内容时可拖元素存在但用户无从下手；另发现桌面鼠标需长按 400ms 才激活 | 桌面鼠标按住移动 8px 即激活拖拽；触屏仍为长按 400ms |
| 左右滑动不行 | 第 4 轮重构时误删了滑动手势 | 恢复：main 区横向滑动（|dx|>60 且 |dx|>1.5|dy|）切换 今天→周课表→月历，拖拽进行中屏蔽 |
| 临时调课"成功"但无效果 | 弹窗允许对学期外日期临时调课，而学期外无课，调整不可见 | 学期外日期禁用"仅当天"选项，弹窗说明原因，仅保留整学期调课 |
| 跨天调课顶掉目标日课程（重大模型缺陷） | ADJ 结构为 {date, from, to}，把"周一第3节→周五第4节"当成同日换节次，在周一这天同时删 from 和 to 节次 | 重构为 {fromDate, fromP, toDate, toP}：调出日删课（格子淡化+“调出”角标），调入日加课（格子显示调入班级+“调”角标），两端日期独立生效 |
| doMove 参数错位（回归） | 改调用格式后函数签名未同步，fromDate 存成 undefined | doMove 内按 type 分别解析参数 |

验证（browser-use，390×844）：六.5 周一第3节拖到周五第4节 → 周一格淡化带"调出"、周五格显示六.5带"调"；周一面板剩 四.4/四.7（四.4 不再被顶掉）✓；周五面板第4节出现"六.5（临时调课）" ✓。测试用学期起点模拟后已恢复 2026-09-01 并清空调课记录。

遗留观察：拖拽成功弹窗可能被键盘/滚动遮挡的极端情况未测；触屏真机长按手感待用户实测（开放问题 #1 不变）。

## 2026-08-29 第 7 轮：用户真机/浏览器实测反馈 4 项修复

| 反馈 | 根因 | 修复 |
|------|------|------|
| 取消调课后"课程悬浮"残留且切换视图不消失 | ghost 元素挂在 body 上，仅在正常 mouseup 路径清理；touchcancel/切视图/关弹窗路径不清理 | 新增 clearDragState()：setTab、touchcancel 统一清除 ghost 与 dragging/droptarget 状态 |
| 周课表要显示日期（滑动才有意义） | 列头只有星期文字 | 列头加日期小字（如 周一 8/24），列头可点选当天 |
| 手机长按触发选择文字 | 缺 user-select 禁用 | .cell/.grid/.hd/.slot 加 user-select:none + -webkit-touch-callout:none |
| 弹窗没有"临时调课"选项 | 第 6 轮把学期外日期的临时选项整个禁用了，而测试时整周都在开学前，永远看不到该选项 | 改为任何日期都允许临时调课（假期补课场景合理）：lessonsOn 的调出/调入对任意日期生效，基课表仍仅学期内展开；弹窗加说明文字区分两种调课 |

回归验证（browser-use 390×844）：列头显示"周一 8/24"等 ✓；拖拽弹窗含 取消/仅当天/整学期 三选项及说明 ✓；取消后 ghost/mask 均清除 ✓；拖拽中途切视图 ghost 清除 ✓。

工程教训：用脚本批量替换内联 JS 时，替换文本里多了一个反引号导致模板字符串提前闭合、整个 script 崩掉（页面白屏）——**补丁后必须 node --check 提取脚本做语法校验再部署**（已纳入流程）。另：browser-use 输入通道偶发停滞（cua 事件不到达页面），先 set(true) 恢复可见性/焦点再重试，属于测试环境问题而非页面 bug。
